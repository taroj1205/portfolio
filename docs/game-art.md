# Game art

Art that a game draws on canvas and also shows in its OG image and games-list card is written once as SVG strings, as 餅つき and ポイ一枚伝説 do in their `_lib/art.ts`. Build them with the gradient, path and document helpers in `src/app/games/_lib/svg.ts`. Each part is a sprite (an SVG body and its box in a 1000-unit scene), so filters such as `feTurbulence` wood grain, masks and blurs look the same everywhere.

- Canvas: `createAtlas` in `src/app/games/_lib/atlas.ts` takes the game's sprites and its `backdrop(width, height, frame)`, rasterizes each sprite once per scale through an `<img>` with a data URI and keeps the bitmaps. The renderer only moves and blends bitmaps each frame. Re-rasterize only when the scale changes by more than a few percent, never per frame.
- OG: `next/og` (satori) renders filters, masks and blurs inside a data-URI SVG. Pass the whole scene from `sceneDoc` as a `backgroundImage` on a `div`, so the route needs no `<img>` lint exception. Satori ignores `x` and `y` on a nested `<svg>`, so place groups with `transform`.
- Games-list card: the card's layers are served as static SVG from `art/[layer]/route.ts` (`dynamicParams = false`, cached daily in `next.config.ts`) and stacked as `<image>` elements, so the list page doesn't inline about 100 KB of SVG. CSS `transform-origin` on those layers is in the card's viewBox units.
- Keep every gradient, filter and clip id unique across sprites, because a composed document holds them all. `art.test.ts` checks that ids don't repeat and that every `url(#…)` points at a defined id.
- When a scene draws the same sprite many times (a school of goldfish), put each sprite body once in `<defs>` under its own id and place copies with `<use href="#…">`, as `sceneDoc` in `src/app/games/kingyo/_lib/art.ts` does. Pasting the body twice repeats its gradient ids.
- When the layout moves the scene (a result sheet shrinking the stage), ease the frame and draw the backdrop bitmap mapped from the frame it was rendered for. Fading between two backdrops rendered for different frames shows a ghost edge.
- For real volume, light a sprite with `relief` in `art.ts`: `feDiffuseLighting` and `feSpecularLighting` on its blurred alpha, which both Chrome and `next/og` render. Keep its surface noise (`skin`) near zero on smooth things such as mochi, or the surface looks pitted. Light small repeated shapes such as rice grains one by one with a gradient and a shadow, because one relief over the group melts them into a single crumpled surface.
- A sprite is rasterized on its own in the game, so it can only use ids it defines. `art.test.ts` checks each sprite as a standalone document too.
