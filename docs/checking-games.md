# Checking games

- `bun run spell` checks with `en-GB`, so code and copy use British spellings (`colour`, `vigour`). Add a new game's romanised name to `words` in `cspell.json`.
- To check a timed game to the hundredth, send touches over CDP with `Input.dispatchTouchEvent` and a `timestamp` in epoch seconds. The page's `event.timeStamp` follows it, so a stop at exactly 10.00s after the start can be replayed instead of hoped for.
- Run the tests with `bunx vp test run src/app/games`. There is no `test` script, and `bun test` uses its own runner, so every `vi.*` call fails there.
- To rewrite Japanese text across files with `perl -i -pe`, pass `-Mutf8 -CSD`. Without `-Mutf8` a Japanese pattern silently matches nothing.
- `bunx vp check` stops at the first formatting problem and prints no lint or type errors. Run `bunx vp check --fix` to format, then read the lint output it prints. The lint rejects nested ternaries, functions with complexity over 20, and colour literals in JSX attributes (`fill="#fff"`); keep colours in a `const` object and pass `fill={paint.moon}`.
- In a fresh checkout, run `bunx next typegen` before `bunx vp check`, or every page reports `PageProps` as an error type.
- The lint also runs anti-slop and shadcn rules: no `typeof` narrowing, no `Record<string, unknown>` prop bags, no `shape` anywhere in an identifier (`no-shape-in-symbol-names`; name it for its role, as 一刀's `Food`), no prop called `style` on your own components (shadcn `no-inline-styles`; take StyleX styles as `xstyle`), and no object keys that start with `handle` (`jsx-handler-names`). It also flags zod `.catch()` as a promise; use `.default()` with a `.transform()` fallback instead.
- `bunx vp check --fix` rewrites `list[list.length - 1]` to `list.at(-1)`, which is `T | undefined` and then fails the type check. Keep the last entry in its own constant or destructure `const [a, b] = list.slice(-2)`.
- In `agent-browser`, `keydown Space` sends an empty `key`, so a game listening for `" "` never sees it. Hold the space bar with `agent-browser keydown " "` and release it with `agent-browser keyup " "`.
- `agent-browser` has no touch tap for Chrome pages. For 390×844 touch play, set the size with `agent-browser set viewport 390 844`, connect to `agent-browser get cdp-url`, attach to the page target, and send `Emulation.setTouchEmulationEnabled` then `Input.dispatchTouchEvent` with `touchStart` and `touchEnd` on that same connection. Touch emulation ends when the CDP session detaches, so enable it again on every connection. End every touch id before the next `touchStart`, or Chrome reads the new start as a move and the page sees no `pointerdown`.
- `agent-browser mouse move` rejects decimal coordinates with "Missing arguments", so round them first. Give it absolute screenshot paths; a relative one is written to the daemon's working directory, which is often the repo root. Set `AGENT_BROWSER_SESSION` to your own name, because other agents can drive the default session. `agent-browser find text … click` can match hidden text such as a canvas fallback; click the `ref` from `agent-browser snapshot -i` instead.
- `agent-browser record start` opens a fresh browser context without the page's `localStorage`, so the recording starts on the language picker with an empty save. Once recording, set `games.settings.v1` (and clear or seed the game's save) with `Runtime.evaluate`, then navigate to the page you want, and trim the lead-in with `ffmpeg -ss`. It also records at only 10 fps. For smooth gameplay, capture Chrome's screencast over CDP (`Page.startScreencast`, answering each frame with `Page.screencastFrameAck`) and build the video from the frame timestamps.
- A canvas game that swaps the prompt for an in-play HUD must keep the stage the same size. If the canvas moves when play starts, every input after the first lands off target. Keep the prompt mounted and hidden, as 型抜き does in `src/app/games/katanuki/_components/game.tsx`.
- In mizukiri, a robot that taps perfectly never loses the stone, so a test that taps until the flight ends can run forever. Pass `play` a throw cap (it defaults to 400) and keep seeds few, because a hop of several km costs about 6ms to simulate.
- To tune mizukiri's difficulty, run `launch` and `land` from a `bun` script and tap with a Gaussian lead around 10ms. A tap spread of 5ms, 12ms and 20ms should end in Milky Way, Snow village and Maple gorge; `reachOf` in `simulate.test.ts` holds the same check.
- The HUD corner holds sound, language and report as three 44px icons. Where the stage sits in the flow below the header (円相, 一刀, 型抜き, 居合, 消しボウ), keep them in one row: `top` is `flex-wrap: wrap`, so a title that ends past about 210px at 390px makes the whole corner wrap under it and moves the stage. Check `getBoundingClientRect().top` of the first and last corner buttons at 390 and 375 wide, idle and mid-run, in both languages, and trim the header's `columnGap` or the title size before adding a control. Where the canvas is full screen (間, 餅つきマスター, 火玉の一生, 星合), stack the corner in a column instead, so the title width never matters.
