# Checking games

- `bun run spell` checks with `en-GB`, so code and copy use British spellings (`colour`, `vigour`). Add a new game's romanised name to `words` in `cspell.json`. CI runs a different cspell (`cspell-action`) that knows fewer words than `bun run spell`: it flagged `worktree` until that went into `words`. Add a technical term there even when the local run accepts it.
- To check a timed game to the hundredth, send touches over CDP with `Input.dispatchTouchEvent` and a `timestamp` in epoch seconds. The page's `event.timeStamp` follows it, so a stop at exactly 10.00s after the start can be replayed instead of hoped for.
- Run the tests with `bunx vp test run src/app/games`. There is no `test` script, and `bun test` uses its own runner, so every `vi.*` call fails there.
- To rewrite Japanese text across files with `perl -i -pe`, pass `-Mutf8 -CSD`. Without `-Mutf8` a Japanese pattern silently matches nothing.
- `bunx vp check` stops at the first formatting problem and prints no lint or type errors. Run `bunx vp check --fix` to format, then read the lint output it prints. The lint rejects nested ternaries, functions with complexity over 20, and colour literals in JSX attributes (`fill="#fff"`); keep colours in a `const` object and pass `fill={paint.moon}`.
- In a fresh checkout, run `bunx next typegen` before `bunx vp check`, or every page reports `PageProps` as an error type.
- After fixing a StyleX build error, such as "Could not resolve the path to the imported file" or a `SyntaxError` from `stylex.keyframes`, `next dev` keeps serving the failed `games.css` with a 500 until you stop it, delete `.next/dev` and `.next/cache`, and start it again.
- `stylex.keyframes` takes only an object literal written in the call, and StyleX names keyframes by their content, so two calls with the same frames share one name and swapping between them never restarts the animation. To replay an animation on every input without remounting the element, call `element.animate()` from an effect, as `useThud` in `src/app/games/tenbin/_components/daily.tsx` does.
- On canvas, cull text whose font size runs to thousands of pixels when the camera zooms in. A `fillText` at a 4,000px font size dropped 月までチーズ to 2 fps even though the text was off screen.
- The lint also runs anti-slop and shadcn rules: no `typeof` narrowing, no `Record<string, unknown>` prop bags, no `shape` anywhere in an identifier (`no-shape-in-symbol-names`; name it for its role, as 一刀's `Food`), no prop called `style` on your own components (shadcn `no-inline-styles`; take StyleX styles as `xstyle`), and no object keys that start with `handle` (`jsx-handler-names`). It also flags zod `.catch()` as a promise; use `.default()` with a `.transform()` fallback instead.
- `bunx vp check --fix` rewrites `() => undefined` to `() => {}` and `str.split("")` to `[...str]`, and the lint then rejects both (`no-empty-function`, `no-misused-spread`). Pass a function that does something, make the callback optional, or index with `charAt`.
- A game without a canvas session can't load its save with `setState` in an effect (`set-state-in-effect`). Render it only once a `useSyncExternalStore` snapshot exists on the client and load the save with lazy `useState`, as `Game` and `Play` in `src/app/games/tenbin/_components/game.tsx` do.
- `bunx vp check --fix` rewrites `list[list.length - 1]` to `list.at(-1)`, which is `T | undefined` and then fails the type check. Keep the last entry in its own constant or destructure `const [a, b] = list.slice(-2)`.
- In `agent-browser`, `keydown Space` sends an empty `key`, so a game listening for `" "` never sees it. Hold the space bar with `agent-browser keydown " "` and release it with `agent-browser keyup " "`.
- `agent-browser` has no touch tap for Chrome pages. For 390×844 touch play, set the size with `agent-browser set viewport 390 844`, connect to `agent-browser get cdp-url`, attach to the page target, and send `Emulation.setTouchEmulationEnabled` then `Input.dispatchTouchEvent` with `touchStart` and `touchEnd` on that same connection. Touch emulation ends when the CDP session detaches, so enable it again on every connection. End every touch id before the next `touchStart`, or Chrome reads the new start as a move and the page sees no `pointerdown`.
- `agent-browser mouse move` rejects decimal coordinates with "Missing arguments", so round them first. Give it absolute screenshot paths; a relative one is written to the daemon's working directory, which is often the repo root. Set `AGENT_BROWSER_SESSION` to your own name, because other agents can drive the default session. `agent-browser find text … click` can match hidden text such as a canvas fallback; click the `ref` from `agent-browser snapshot -i` instead.
- `agent-browser record start` opens a fresh browser context without the page's `localStorage`, so the recording starts on the language picker with an empty save. Once recording, set `games.settings.v1` (and clear or seed the game's save) with `Runtime.evaluate`, then navigate to the page you want, and trim the lead-in with `ffmpeg -ss`. It also records at only 10 fps. For smooth gameplay, capture Chrome's screencast over CDP (`Page.startScreencast`, answering each frame with `Page.screencastFrameAck`) and build the video from the frame timestamps.
- A canvas game that swaps the prompt for an in-play HUD must keep the stage the same size. If the canvas moves when play starts, every input after the first lands off target. Keep the prompt mounted and hidden, as 型抜き does in `src/app/games/katanuki/_components/game.tsx`.
- In mizukiri, a robot that taps perfectly never loses the stone, so a test that taps until the flight ends can run forever. Pass `play` a throw cap (it defaults to 400) and keep seeds few, because a hop of several km costs about 6ms to simulate.
- To watch mizukiri past 100 km (大海原 and beyond) in a browser, temporarily patch the `release` handler in `session.ts` to launch on a fixed `createRiver(seed)`, `land` with `contact - 0.01` until about 60 s of flight, then set `time` there, and in `advance` pass `contact - 0.01` instead of `tap`. Revert it afterwards. Perfect taps send the stone into high hops that pull the camera back, so sideways problems show only on low skims, often 20–30 s after reaching the sea.
- To tune mizukiri's difficulty, run `launch` and `land` from a `bun` script and tap with a Gaussian lead around 10ms. A tap spread of 5ms, 12ms and 20ms should end in Milky Way, Snow village and Maple gorge; `reachOf` in `simulate.test.ts` holds the same check.
- To tune てっぺんかき氷, run `step` from a `bun` script with bots that pour at the centre, steer with `steer` from `_lib/demo.ts` after a 0.2s delay, and swing the glass about. A tilted mound under the fixed stream corrects itself a little, because the ice lands on its uphill side, so the centre bot only fails when that free correction is weaker than the growth and a steering player beats it only by moving further. Keep the steering bot serving about 15cm and the centre and swinging bots toppling, as `pile.test.ts` checks; change `NUDGE`, `GROW` and the slumps together, and rerun the bots after any change to the slope or stream width, since a wider mound spends longer at each height.
- The report flag is in every game's HUD corner at all times. 水切り has no language icon, because its language switch lives in the workshop settings, so its corner is sound, workshop or reset, and report. In the other games the corner holds sound, language and report as three 44px icons. Where the stage sits in the flow below the header (円相, 一刀, 型抜き, 居合, 消しボウ, ポイ一枚伝説, 一億トン天秤, てっぺんかき氷), keep them in one row: `top` is `flex-wrap: wrap`, so a title that ends past about 210px at 390px makes the whole corner wrap under it and moves the stage. Check `getBoundingClientRect().top` of the first and last corner buttons at 390 and 375 wide, idle and mid-run, in both languages, and trim the header's `columnGap` or the title size before adding a control. Where the canvas is full screen (間, 餅つきマスター, 火玉の一生, 星合, 月までチーズ, 水切り), stack the corner in a column instead, so the title width never matters.
- Before calling a touch game fair, replay it at 390×844 with CDP touch bots: one that touches straight on the target, one that spams the cheapest shortcut, and one that plays carefully. In ポイ一枚伝説 a quick tap 56px below each fish once scored 16 while a straight tap scored 1 in 10, which the unit tests could not show. Every rule that limits a shortcut has to show on screen, or players read it as broken hit detection: a hidden rule that let a startled fish slip off caught only 5 of 144 dips made right onto a fish. Now a fish dipped on stays drawn under the paper and the lift says "Under the paper!", and only fish on top of the paper come up, while the wet paper hides the ones underneath. On touch the finger holds the poi by its handle, because a game where you wait and watch the paper can't have it under a thumb. `tank.test.ts` checks that dipping ahead beats tapping on fish.
- Read drag speed for wear or scaring from a smoothed velocity, never from one pair of samples. A finger's tiny wobble over an 8ms sample gap reads as a fast sweep, and phones send 60 to 240 samples a second, so the raw speed tears the paper faster on faster screens.
- A screenshot taken right after an input can catch a tween halfway, such as ポイ一枚伝説's fish still flying to the bowl or its ripples still spreading. Take a second screenshot a second later before treating it as a timing bug.
- On touch, Chrome keeps an `AudioContext` suspended until the finger lifts, so `resume()` on `pointerdown` does nothing for a player whose first input is a drag. Call the sound's `unlock` in the pointer-up handler too. To check it, wrap `AudioContext` in `Page.addScriptToEvaluateOnNewDocument` and read each instance's `state` after `Input.dispatchTouchEvent` starts and ends a touch.
- A CDP script that sends `Input.dispatchTouchEvent` to a tab that `next dev` hot-reloaded after an edit can hang on the first touch. Close the agent-browser session and open a fresh one after editing.
- Mizukiri speeds are metres per second (`speedAt`, `topSpeed`); the HUD shows them in km/h through `toKmh`, which is ×3.6.
- To throw a mizukiri stone from a browser tool, dispatch `keydown` and `keyup` for `Space` on `window` in one `Runtime.evaluate`, with `timeStamp` overridden to 5000 and 5400 through `Object.defineProperty`. Every run then holds exactly 0.4s and flies the same path; a `setTimeout` hold does not. Patch `session.ts` to a fixed `createRiver(7)` and `land(current, contact - 0.01)` for perfect taps, and stop tapping once `topSpeed(current)` passes the speed you need if the run has to end and show the result sheet. Check with `rg "createRiver\(7\)|contact - 0.01" src` that the patch is gone afterwards.
- To compare mizukiri versions side by side, record each run with a CDP screencast from `agent-browser` (`Page.startScreencast`, frames at 1x, video built from the frame timestamps), not with the T3 `preview_recording_*` tools. The water shader from before `be8524e` froze the T3 preview tab, and after that `preview_recording_start` timed out and the game ran at 2 fps. To check an old version, copy the current `water.ts` over it.
- Line the panels up by the HUD distance, not by a detected key press: trim each clip until the metres read within a few of each other at 14s and 17s. Stack the clips side by side with `ffmpeg`. This build has no text-drawing filter, so draw the labels into a PNG with Swift and AppKit (`NSAttributedString`, `HiraginoSans-W6`), scale it from its 2x size to the video width, and `overlay` it on a padded top bar.
- On 目分量十番勝負, a DOM game, try `preview_snapshot` first. If it times out while `preview_evaluate` still works, take screenshots with `agent-browser`. To bot-play it, print the answers for a seed with `puzzlesOf` from a `bun` script, open a challenge link with that `s`, and click them with `agent-browser mouse`.
- If `preview_snapshot` keeps timing out on a canvas game, read the 2D scene canvas with `getImageData` one row at a time and note where the bright pixels start and end. Returning `canvas.toDataURL()` from `preview_evaluate` floods the reply.
- In `agent-browser`, run `set viewport 390 844 2` after the browser is up, `open` the page, and read `innerWidth` before taking screenshots; a session closed and reopened came back at 1280 wide. Phone screenshots are 780×1688, and the Next.js dev badge sits near y=1575, so crop to 1520 for PR images.
- Port 1205 can be taken by a `next dev` from another worktree. Check `lsof -iTCP:1205` before starting one, use another port if it is taken, and stop only the server you started. `next dev` also edits `AGENTS.md`; run `git checkout -- AGENTS.md` before staging.
- A PR that changes a game's look gets a same-timing side-by-side video, the changed screen on `main` and on the branch at 390×844 and 2x, and no diff overlay when the screen sits on the live canvas, because the pixels differ between any two shots. The mizukiri tip screenshots need a throw that reaches the result sheet.
